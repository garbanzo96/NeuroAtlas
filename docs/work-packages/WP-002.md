# WP-002: Activar CI, rama principal y protección de rama

- **Hito:** M1 · **Ejecutor recomendado:** U (usuario) con apoyo de C · **Depende de:** — · **Tamaño:** S

## Objetivo

Que todo cambio llegue a la rama principal solo a través de un PR con CI en verde.

## Contexto

El repositorio se creó con la rama `claude/neuroscience-interactive-base-wgbx0a`. CI está definido en
`.github/workflows/ci.yml` (ADR-0009). Sin protección de rama, un modelo podría empujar cambios que rompan la
arquitectura o el validador.

## Pasos

1. En GitHub, crear `main` a partir de la rama actual (o fusionar la rama mediante un PR) y fijarla como rama
   por defecto (_Settings → General → Default branch_).
2. _Settings → Actions → General_: permitir GitHub Actions.
3. _Settings → Branches → Add rule_ (o _Rulesets_) para `main`: exigir PR, exigir que pase el check
   "Comprobaciones (formato, lint, tipos, fronteras, contenido, pruebas, build, e2e)", prohibir force-push.
4. Comprobar que el último push muestra el check en verde.

## Criterios de aceptación

- `main` es la rama por defecto y está protegida (PR + check obligatorio).
- El workflow CI pasa en `main`.
- `docs/backlog.md` marca WP-002 como hecho.
