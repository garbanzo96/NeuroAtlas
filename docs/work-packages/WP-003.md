# WP-003: Vista previa pública en GitHub Pages

- **Hito:** M1 · **Ejecutor recomendado:** M · **Depende de:** DEC-007 (hosting y visibilidad), WP-002 · **Tamaño:** S

## Objetivo

Publicar automáticamente la app (build estático) en GitHub Pages en cada push a `main`, para que docentes y
asesores la prueben sin instalar nada.

## Contexto

La app es estática (ADR-0001/0002). `apps/web/vite.config.ts` admite `NEUROATLAS_BASE` para servir bajo un
subdirectorio (`/NeuroAtlas/`). El cargador de paquetes y el Worker ya usan rutas relativas a la base.

## Archivos

- Leer: `apps/web/vite.config.ts`, `apps/web/src/data/pack-loader.ts`, `.github/workflows/ci.yml`, `package.json`.
- Crear: `.github/workflows/pages.yml`.
- Modificar: `README.md` (enlace a la vista previa), `docs/backlog.md`.
- No tocar: código de `packages/` y `apps/web/src/`.

## Pasos sugeridos

1. Workflow con `on: push: branches: [main]` y `workflow_dispatch`, permisos `pages: write`, `id-token: write`.
2. `npm ci` → `NEUROATLAS_BASE=/NeuroAtlas/ npm run build` → subir `apps/web/dist` con
   `actions/upload-pages-artifact` → `actions/deploy-pages`.
3. No desplegar si `npm run check` falla (ejecutarlo antes o depender del job de CI).

## Criterios de aceptación

- `NEUROATLAS_BASE=/NeuroAtlas/ npm run build` funciona en local y el `dist/index.html` referencia `/NeuroAtlas/assets/...`.
- Tras el despliegue, la URL de Pages carga la vía visual, la ficha y la simulación (Worker) sin errores de consola.
- `npm run check` sigue en verde.

## Fuera de alcance

Dominio propio, analítica, service workers.
