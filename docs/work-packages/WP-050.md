# WP-050: Mapeos espaciales y transiciones registradas

- **Hito:** M3+ · **Ejecutor recomendado:** C (contrato nuevo) · **Depende de:** — · **Tamaño:** M

## Objetivo

Introducir la colección `content/mappings/` (`SpatialMapping`) para que una transición pueda declararse
`registered` cuando exista un registro espacial documentado entre los marcos de dos escenas.

## Contexto

Hoy el validador prohíbe `registered` (código `TRANSITION_REGISTERED_UNSUPPORTED`, ADR-0005). Será necesario
cuando varias escenas compartan un espacio de atlas (p. ej. superficie y cortes en el mismo espacio de referencia).
El plan (02 §4) exige: espacios origen/destino, método (afín, no lineal, superficie, entre especies), parámetros o
archivo, versión, restricciones, error evaluado y procedencia; una transformación entre especies no establece homología.

## Diseño propuesto (cerrar en un ADR)

- `SpatialMapping { id: map.*, fromFrameId, toFrameId, kind: identity|affine|nonlinear|surface,
method, parameters | file, version, error: { value, units, method } | null, constraints, provenance, sourceIds }`.
- Validador: `registered` exige `spatialMappingId` existente cuyos marcos coincidan con los de las escenas;
  ningún mapeo entre contextos de especies distintas puede usarse como `registered`.
- Interfaz: el aviso de transición muestra método y error; con registro válido, la cámara puede conservar el
  encuadre (opcional, respetando movimiento reducido).

## Criterios de aceptación

- ADR nuevo, esquema exportado, pruebas del validador (casos válido e inválidos) y de la interfaz.
- Ninguna escena del release actual cambia a `registered` sin un mapeo real y documentado.
- `npm run check` y `npm run e2e` en verde.
